# Factory upgrades

`saasforge.manifest.json` records the factory version, template version, product blueprint, and SHA-256 fingerprint of every generated file. Run `pnpm product:changes` to see which managed files the product has customized or deleted.

Factory upgrades follow a three-way policy:

1. The old manifest fingerprint is the common base.
2. The current product file is the product-owned side.
3. The same blueprint generated by the target factory version is the factory-owned side.

An updater may replace a file automatically only when its current fingerprint still matches the old manifest. Customized or deleted files are conflicts and must never be overwritten silently. Review those files manually, preserve the product's design and business logic, then record the new manifest only after all quality gates pass.

Before upgrading, create a branch and a recoverable commit. Read the target release notes, regenerate the same blueprint in a disposable directory, compare dependency and migration changes, and apply upgrades in small groups. Database migrations use expand/migrate/contract and are never rolled back blindly.

The factory version is not a claim that every copied dependency is current. Dependabot, security workflows, and product-specific review continue independently after generation.
