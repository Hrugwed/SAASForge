# Security policy

## Supported versions

Security fixes are applied to the latest release on `main`. Before the first stable release, older snapshots are not supported.

## Report a vulnerability

Do not open a public issue. Use GitHub private vulnerability reporting on this repository. If private reporting is unavailable, contact the repository owner privately and include the affected version, impact, reproduction steps, and any suggested mitigation. Do not include real credentials or customer data.

We aim to acknowledge a complete report within three business days, provide an initial assessment within seven business days, and coordinate disclosure after a fix is available. These are response targets, not a warranty.

## Scope

Reports about authentication, authorization, tenant isolation, billing/webhooks, generation path safety, secrets, CI, provider adapters, and generated product defaults are welcome. Provider outages, social engineering, denial-of-service requiring unrealistic resources, and findings without security impact are generally out of scope.
